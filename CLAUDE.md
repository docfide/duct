# CLAUDE.md

Duct (`@docfide/duct`) is a TypeScript document-intelligence pipeline: extract → chunk → embed → search → ask. It ships as a CLI (`duct`), a Node library (`Duct` class), an Express server with a built-in web UI, and an Electron desktop wrapper.

## Commands

```bash
npm install
npm run dev -- <cmd> [args]   # run CLI from source via tsx, e.g. npm run dev -- index ./docs
npm run serve                 # tsx src/cli.ts serve → http://localhost:3456
npm test                      # vitest run (test/**/*.test.ts)
npx vitest run -t "BM25"      # run tests matching a name
npm run typecheck             # tsc --noEmit
npm run build                 # tsc → dist/
npm run electron:dev          # build, then launch Electron
npm run icons                 # regenerate app/tray icons from assets/mascot SVGs
npm run bench -- <folder> [queries.json] [--ocr]   # index speed, search latency, top-3 accuracy (needs a build)
npx electron-builder --mac dir -c.mac.identity=null # unsigned packaged app in release/ for local testing
```

When launching Electron from a VS Code terminal, unset `ELECTRON_RUN_AS_NODE` first (`env -u ELECTRON_RUN_AS_NODE npm run electron:start`). Otherwise Electron runs as plain Node and `require('electron')` fails.

CI (`.github/workflows/ci.yml`) runs typecheck and tests on Linux, macOS and Windows, plus a build. Publishing to npm and GHCR happens on a GitHub release (`publish.yml`). Desktop installers aren't built in CI yet: signing and notarization need Apple and Windows certificates.

## Layout

```
src/
  index.ts        Duct class: the whole pipeline, change detection, config, watched folders, diff, schema extraction
  library.ts      addToLibrary(): copy a file into the Library (~/Duct Library), dedupe by hash, index it
  version.ts      VERSION read from package.json
  types.ts        All public interfaces (DuctConfig, RuntimeConfig, Chunk, Searcher, VectorStore, LLMProvider, …)
  cli.ts          commander CLI: index, search, ask, watch, extract, diff, serve
  server.ts       Express REST API (/api/*) + the entire web UI as an inline HTML string (`const html`)
  dommatrix.ts    DOMMatrix polyfill that pdfjs-dist needs in Node (borrows canvas's, else a 2D fallback)
  extract/        Per-format extractors (pdf, docx, md, html, txt, xlsx, pptx, image, url) + table detection
  chunk/          sliding-window and by-heading chunkers
  embed/          One file per embedding provider + factory.ts (createEmbedder)
  search/         bm25.ts, hybrid.ts (HybridSearcher + reciprocalRankFusion), reranker.ts (SimpleReranker/Noop)
  store/sqlite.ts SqliteStore: the index (documents, chunks, FTS5, vectors, versions, settings, sources) on node:sqlite
  store/memory.ts Standalone in-memory vector store (public API only; Duct itself uses SqliteStore)
  qa/provider.ts  LLM providers: OpenAI, Gemini, Ollama + createLLMProvider
  api/            Developer API: v1.ts (the /v1 router), collections.ts (one Duct index per collection), openapi.ts, client.ts (TS client)
  ocr/            tesseract.js (one shared worker, bundled model in assets/ocr) + sharp; pdf.js renders scanned pages
electron/         main.cjs / preload.cjs: starts the dist/ server on a free port and loads it in a BrowserWindow
                  icon.png / icon.icns / icons/tray*.png are GENERATED by `npm run icons` (scripts/build-icons.mjs)
assets/mascot/    Mascot art: mascot.lottie (all animations), pose-*.svg/.gif, app-icon.svg, tray-template.svg
assets/mascot-archive/  Superseded mascot files and the pre-mascot icons; not shipped
assets/ocr/       eng.traineddata, the Tesseract model (unpacked from asar in Electron builds)
test/             duct, index-store, library, security, server, extract-pdf suites + fixtures/
docs/             User docs: cli, api, library, search, qa
```

## Architecture notes

- **ESM + NodeNext.** Relative imports must use the `.js` extension (`./search/bm25.js`) even in `.ts` files.
- **Heavy and optional deps are lazy-loaded** with `await import(...)` inside functions (pdfjs, mammoth, sharp, tesseract, openai, xlsx, jszip, provider SDKs). Keep it that way so a missing optional dependency only breaks that one format or provider.
- **Provider auto-detection from env.** `createEmbedder()` picks the first key it finds in this order: OPENAI, GEMINI, COHERE, VOYAGE, MISTRAL, JINA (`*_API_KEY`). With no embedder, Duct is BM25-only. If no `llm` config is given, the LLM is OpenAI, then Gemini, from env keys. Otherwise `createLLMProvider` defaults to Ollama (`llama3.2` at `localhost:11434`).
- **Storage is SQLite (`node:sqlite`, Node ≥ 22.13).** `SqliteStore` holds everything in `<persistPath>/duct.db`, or `:memory:` without a persistPath, so both cases share one code path. Keyword search is FTS5 with the `porter unicode61 remove_diacritics 2` tokenizer and `bm25()` ranking. CJK text is matched with LIKE substrings. Metadata filters are SQL `json_extract` conditions, applied before the limit. An old JSON index (`meta.json`/`bm25.json`/`vectors.json`/`config.json`) is migrated on first open and renamed `*.migrated`.
- **Search.** The default mode is `bm25`. `vector`/`hybrid` only take effect when an embedder exists, and they fall back to keyword search if embedding fails or no vectors exist yet. The optional rerank runs last.
- **Pages.** Extractors can return `pages` (PDF pages, PPTX slides). `chunkDocument()` chunks page by page and sets `chunk.page`. Search results carry an FTS5 `snippet()` with \u0002/\u0003 markers; `markSnippet()` in the page escapes and then marks them. Schema v2 added `chunks.page`, and older PDF/PPTX documents are marked stale and re-extracted by `refreshStale()`.
- **Change detection.** Documents store mtime, size and a sha256 of the file bytes. `index()` skips unchanged files and serializes work per path (`withLock`), so concurrent calls never duplicate chunks. Failed extractions are stored with `status: 'failed'` (excluded from `stats()`), and empty ones with `status: 'no-text'`. The last 2 versions per path are kept for `diff`.
- **Embeddings** are keyed by model (`embedKey()`). `embedPending()` fills in missing or stale vectors in batches, and changing the model in `configure()` re-embeds in the background.
- **Watched folders** (`watch`, `restoreSources`, `removeSource`) are stored in the `sources` table. Events are debounced 300 ms per path, and deletes or renames remove documents. `restoreSources()` reconciles on startup; Electron and `duct serve` call it.
- **Settings.** `configure()` saves only the keys passed to it, never API keys, which stay in `process.env`. Saved settings are reapplied on open unless the constructor sets them explicitly.
- **Server specifics.** By default it accepts only loopback Host headers and rejects cross-origin writes. It sends a CSP and requires `--auth-token` to listen beyond localhost; the browser UI gets an HttpOnly cookie through `POST /api/login`. Uploads land in `<library>/.incoming`, then move into the Library (`~/Duct Library` by default) under their real names via `addToLibrary`. `DELETE /api/documents` only deletes files with `source: 'library'` inside the library. `/api/watch` only accepts folders under `--watch-root`. The rate limit (120/min) applies only when a token is set.
- **Web UI** is static files in `assets/ui/`: `index.html`, `app.css` and `app.js` (a plain ES module with no build step). It gets server facts from `GET /api/info`. The page's CSP forbids inline scripts, so attach every handler in `app.js` and never use `onclick=` or inline `<script>`. Use `esc()` for anything inserted as HTML and `textContent` for model output. The desktop app calls `window.duct.{refresh, showFailed, focusSearch, openSettings, exportResults}`; keep those working. The island (`src/island.ts`) and viewer (`src/viewer.ts`) are still inline template-literal pages, served with `INLINE_SCRIPT_CSP`. Inside those, `\\` in TS becomes `\` in the page, and `test/server.test.ts` parses all page scripts. Search takes an optional scope (`?formats=pdf,docx&under=/folder`), and file names are matched as well as text.
- **Mascot.** The UI plays poses from `assets/mascot/mascot.lottie` with `@lottiefiles/dotlottie-web`. The server serves the player JS and wasm from `node_modules` at `/vendor/dotlottie/*` and the art at `/mascot/*`. `setWasmUrl` keeps it off the CDN, so it works offline. Animation ids such as `Pose - Working` are mapped in `MASCOT_POSES` in the page script. If the player fails, the page falls back to the static `pose-*.svg`. `assets/mascot` must stay in package.json `files`, electron-builder `build.files`, and the Dockerfile.
- **PDF viewer** (`src/viewer.ts`, `/viewer?path=&page=&terms=`) uses pdf.js's legacy build and `pdf_viewer.mjs` (which reads `globalThis.pdfjsLib`, so it's imported after setting it). Everything is served from `/vendor/pdfjs/*`. Highlight terms come from the snippet's \u0002 markers (`highlightTerms()` in the page and the island), so stemmed matches are highlighted. Keep `box-sizing` rules off the text layer, because they misalign highlights.
- **Island** (`src/island.ts` page + `electron/island.cjs` window + `island-preload.cjs`): a transparent, always-on-top window (an NSPanel on macOS, moved to y=0 after it's shown) across the top centre. Its states are hidden, live, peek, search and drop. The main process polls the cursor every 50 ms and turns click-through on or off for the shape the page reports through `setShape`. The notch is detected by a menu bar of 34 pt or more on the built-in display (`screenMetrics`). Mascot players pause when their section is hidden. The pose `'head'` is not Lottie: it's the live SVG head (`HEAD_SVG`, `trackHeads()`), which follows the cursor position the main process sends as `island:cursor`. Failures come from `activity().lastRun` (tracked by `id`), drop results from `island:add-files` (`unsupported`, `watched`, `failed`), and `showMain('failed')` calls `showFailedDocuments()` in the main page. Desktop preferences (`island`, `sounds`, `greeted`) live in `userData/desktop-settings.json`. Sounds are synthesized with Web Audio in the island page (`SOUNDS`/`sound()`). They only play for user actions or long jobs, never once per file, and the island window sets `autoplayPolicy: 'no-user-gesture-required'` for the first-launch hello.
- **Tray**: `updateTray()` switches between `trayTemplate` and `trayRestingTemplate` (macOS) or `tray`/`trayResting` (elsewhere) every 2 s, based on watched folders and `duct.activity()`. Icons come from `assets/mascot/tray-*.svg` via `npm run icons`.
- **API keys in the desktop app** are encrypted with Electron `safeStorage` into `userData/secrets.bin` (through `createServer({ onSecrets })`) and passed to `duct.configure()` at launch. Elsewhere they live only in memory.
- **Electron** imports `../dist/*.js`, so run `npm run build` before launching it. It holds a single-instance lock, keeps its index in `userData/data`, and copies "Add Files" into the Library. Watching goes through IPC (`duct:watchDirectory`), not the HTTP API. `DUCT_USER_DATA_DIR` and `DUCT_LIBRARY_DIR` override the paths for tests and portable installs.
- **CLI** keeps its index in `$DUCT_HOME` or `~/.duct` (the `dataDir()` helper in `cli.ts`).
- **Account and usage counts** (`src/account.ts`, `src/telemetry.ts`): `TensflareAccount` does PKCE sign-in with a one-shot loopback listener, keeps tokens in an `AccountStorage` (Electron: safeStorage `account.bin`; CLI/serve: 0600 `account.json`) and checks the EdDSA entitlement offline with the cached JWKS. `Telemetry` builds a schema-1 report from enums and ranges only (it must match `parseDuctReport` in tensflare-accounts), counts searches/opens/ask/OCR per UTC day, and sends at most daily from `duct serve` and the desktop app. `DEFAULT_ON` is false until the public field list and privacy notice are reviewed; EU/EEA (OS region) is always opt-in. The test in `test/account-telemetry.test.ts` fails if a report contains any file name, path or word from the indexed documents.
- **Diagnostics and feedback** (`src/diagnostics.ts`): `errorCode()` turns error messages into fixed codes (messages can contain paths), `sanitizeStack()` keeps only frames from `dist/`, `src/`, `electron/` or `assets/ui`, and crash records go to `crashDir` (Electron: `userData/crashes`, serve: `<data>/crashes`, newest 20). `POST /api/feedback` forwards to `FEEDBACK_URL` (tensflare-accounts `/v1/duct/feedback`), adding diagnostics and crashes only when the person ticked them. Tests fail if diagnostics or crash records contain paths, file names or document words.
- **Hosted AI and sync** (`src/hosted.ts`, `src/sync.ts`): the `tensflare` embedding and LLM providers call the account's hosted AI through a client the host registers with `setHostedAi(account.hostedAi())` (Electron and `duct serve`). `SettingsSync` syncs only `SYNCED_SETTINGS` and feature switches through `/v1/sync/settings`, with versions; `PUT /api/config` and `/api/features` call `sync.changed()`. Billing and plan changes happen on the account website, opened with a one-time link (`account.webLink()`).
- **Tags and export** (`src/export.ts`): tags are a `tags(path, tag)` table kept by path, so they survive re-indexing; `SearchScope.tags`/`modifiedAfter`/`modifiedBefore` filter in `filterClause`. Exports build `ExportItem`s (name, location, heading, text) and render CSV (BOM, formula-safe), Markdown, JSON or a minimal .docx via jszip. `toFtsQuery` expands amounts with `numberVariants`. Collected passages live in the page's localStorage (`duct.collected`).
- **Feature switches** (`src/features.ts`): `Features` holds on/off switches and `formats` per `FormatKind`, saved in the settings table under `features`. Constructor `features` win but aren't saved. Enforce a new switch in three places: `requireFeature()` in the library, `needs('<name>')` on the server route, and `applyFeatures()`/`FEATURE_GROUPS` in `assets/ui/app.js`. Format families are filtered in `index()` (`formatAllowed`) and `search()` (`enabledFormats`). Desktop-only switches (island, sounds, shortcut) live in `desktop-settings.json` via `prefs:get`/`prefs:set` IPC.

- **Developer API** (`src/api/`, docs/developer-api.md): `/v1` is mounted before the app-wide JSON parser and has its own parser, key auth (Bearer `duct_…` or the admin token, never cookies), scopes (`search` < `write` < `admin`) and per-key rate limit. Keys live in the `api_keys` table (sha256 only). Each collection is a separate `Duct` at `<index>/collections/<name>` (in memory without a data dir); text documents are stored under the key `text:<id>`, uploaded files at `collections/<name>/files/<id>/<file>`. `Duct.indexText()`, `facets()`, `pageDocuments()` and `documentText()` exist for it. Python client: `clients/python/duct_client.py`.

## Adding things

- **New file format:** add it to `FORMATS` in `src/formats.ts` (extensions, label, kind, optional `pageLabel`), extend `DocumentFormat` in `types.ts`, and add a `case` to `extract()` in `src/extract/index.ts`. Everything else (indexer, upload filter, web UI, desktop dialogs, island) reads the registry. Extractors return `pages` (with page numbers) or `sections` (named parts such as attachments). Throw `UnsupportedFileError` when a file isn't really that format, so it's skipped rather than reported as failed. Put real-format fixtures in `test/formats.test.ts`, generated through `test/helpers.ts` where possible. Update `docs/formats.md`.
- **New embedding provider:** add `src/embed/<name>.ts` implementing `EmbeddingProvider` (`embed()` + `dimensions`), wire it into `createEmbedder`/`guessProvider` in `factory.ts`, and add it to the `EmbedProvider` union and the `DuctConfig.embed.provider` union in `types.ts`. If it needs a key, add it to `RuntimeConfig`, `getConfig()`, and `configure()`.
- **New LLM provider:** implement `LLMProvider` in `qa/provider.ts` and add a branch in `createLLMProvider`.
- **New CLI command / API route:** `cli.ts` (commander) / `server.ts`. Update `docs/cli.md` / `docs/api.md` to match.

## Conventions

- 2-space indent, no semicolons, single quotes, `strict` TypeScript.
- Extraction/indexing errors on one file are logged with `safeWarn` and skipped. They don't abort the batch.
- Tests run offline with no API keys. Keep new tests that way: use fixtures in `test/fixtures/`, temp dirs, and fake local servers (see the fake Ollama in `test/index-store.test.ts`). Never let tests touch `~/.duct` or `~/Duct Library`; pass `persistPath`/`libraryDir` explicitly.
- Note user-visible changes in `CHANGELOG.md` (Keep a Changelog format).

## Known gaps

- The CSP still allows `'unsafe-inline'` scripts because the page uses inline `onclick` handlers; moving them to `addEventListener` would allow a nonce-based CSP.
